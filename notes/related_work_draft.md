## Tool learning and function-calling benchmarks

Teaching language models to call external tools has moved from self-supervised API insertion \citep{schick2023toolformer} and interleaved reasoning and acting \citep{yao2023react} to models trained on large API collections \citep{patil2024gorilla, qin2024toolllm} and on synthetic, verified function-calling data \citep{liu2024apigen, liu2025toolace}. Evaluation has developed in parallel. API-Bank \citep{li2023apibank} and MetaTool \citep{huang2024metatool} first separated deciding *whether* to use a tool from *which* tool to choose. BFCL \citep{patil2025bfcl} standardized scoring through AST matching and is now the common reference for single-turn calling. More recent MCP benchmarks evaluate multi-step tool use against live servers \citep{wang2025mcpbench, luo2025mcpuniverse, mo2025livemcpbench, yin2025livemcp101}. Surveys organize this pipeline into planning, selection, calling and response generation \citep{qu2025toolsurvey}. Most of these benchmarks fix the candidate tool set for each task, so they mix up a model's ability to call a tool with its ability to find the right one among many. Robustness studies show the cost of that mix-up. Adding a few semantically related tools to BFCL lowers accuracy even for 70B-class models \citep{rabinovich2025robustness}. Shuffling the tool order changes success rates \citep{huang2024stability}. Models also favour tools that appear earlier in the context \citep{blankenstein2026biasbusters}, or tools with particular metadata \citep{li2026metadata}.

## Tool retrieval and large tool catalogs

When catalogs grow, accuracy falls. LongFuncEval pads BFCL queries with up to roughly 740 random distractor functions and reports drops of 7–85% for models of 8B parameters and above, with position effects that resemble the lost-in-the-middle pattern \citep{kate2025longfunceval, liu2024lost}. MCP stress tests and similarity-graded distractors show the same pattern \citep{gan2025ragmcp, choi2026toolmath}. The usual fix is to expose only a subset of tools. Approaches include dense or rewritten-query retrieval \citep{chen2024reinvoke, qu2024colt, mudunuri2026semantic}, taxonomy- or plan-conditioned filtering \citep{antonioni2025jsplit, patel2026dtdr, babu2026toolchoiceconfusion}, merging redundant tools \citep{liu2026toolscope}, letting the model request tools itself \citep{fei2025mcpzero}, and encoding tools as vocabulary tokens \citep{wang2025toolgen}. Two findings limit the promise of retrieval. First, general-purpose embedders are poor tool retrievers, and retrieved toolsets lower end-to-end success compared with gold toolsets \citep{shi2025toolret}. Second, the best shortlist length varies from query to query, so a fixed top-k can be judged against a chance baseline \citep{repantis2026howmany}. Almost all of this evidence comes from large, full-precision models. We do not know whether a 2B model gains more from a short list or loses more when the retriever misses the gold tool.

## Small language models as agents and tool users

Arguments for small language models (SLMs) as the default engine for agentic sub-tasks \citep{belcak2025slmfuture, sharma2025slmsurvey} have been followed by on-device function-calling systems. These systems fine-tune 1–7B models, often with 4-bit quantization, and add tool selection through classifiers, functional tokens or function masking \citep{erdogan2024tinyagent, chen2024octopusv2, lin2024hammer, zhang2025xlam}. Splitting tool use across several small models is another option \citep{shen2024smallllms}. Off-the-shelf SLMs, by contrast, often fail on output format and argument filling \citep{kavathekar2025small, mastoi2026beyond, haque2025tinyllm}, and they invent tool names that are not in the schema \citep{lee2026patool}. Compression adds another factor. Quantization can leave aggregate scores almost unchanged while increasing particular failures, such as missed calls, wrong arguments or hallucinated tool names \citep{dong2025acbench, roshaan2026compression, singh2026samequant, ponrajan2026permission, jang2026flatscore}. These conclusions can also reverse depending on the prompt and the scoring policy \citep{hu2026quantrecovery}. The work closest to ours routes a 1.5B model over BFCL tasks padded with distractors and finds that semantic top-8 retrieval alone does not recover accuracy \citep{singla2026agentweave}. That study uses a single model and 48 tasks.

Our study connects these lines of work. We vary catalog size in the small-N regime, distractor similarity, gold-tool position and embedding-based top-k retrieval \citep{chen2024bgem3, zhang2025qwen3embedding} in a controlled way. We test sub-4B quantized instruct models \citep{qwen2024qwen25, grattafiori2024llama3, yang2025qwen3} on consumer hardware, and we report how the mix of failure types shifts along each of these axes.
