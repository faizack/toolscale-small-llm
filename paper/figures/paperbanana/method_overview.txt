We study how small language models (1.5B-3B parameters, quantized, served locally with Ollama on a 4 GB consumer GPU) select and call tools as the number of available tools grows.

Pipeline. (1) Data: we start from the 400 queries of the BFCL v4 simple_python benchmark; each query comes with exactly one gold function (JSON schema) and a set of accepted argument values. (2) Catalog construction: the 400 gold functions form a pool of real tools. For a catalog size N in {1, 4, 16, 64}, the queries are shuffled with a seed and split into blocks of N; the gold functions of a block form that block's tool catalog, so every distractor is the real tool of another task. The catalog order is shuffled and the position of the gold tool is recorded. (3) Condition A, full catalog: the user query plus all N tool schemas are sent to the small LLM through native function calling (temperature 0). (4) Condition B, retrieval: an embedding model (Qwen3-Embedding-0.6B) ranks the N catalog tools by cosine similarity to the query, and only the top-k (k=3) tools are given to the LLM. (5) Raw output capture: the generated tokens are recorded via logprobs, because the serving stack silently drops malformed calls. (6) Scoring: the BFCL AST checker decides strict correctness; a lenient variant coerces string-encoded numbers. (7) Failure taxonomy: every incorrect response is assigned to one category: wrong tool, hallucinated tool, argument error (wrong value, wrong type, missing or extra argument), malformed call, no call, or multiple calls. Outputs are accuracy-vs-N curves, failure distributions, position effects and retrieval gains.
